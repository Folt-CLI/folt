# XL Epic

XL is a release; it only groups the work and is always an Epic.

## The ticket must contain

Title it `<version> -- Folt`. The body contains only `## Objective` and a short release explanation. Set type Epic and the milestone, Priority, Size, Status and ownership from the [shared steps](../rules.md#shared-steps).

## Analysis and review

XL needs no analysis and no review. Follow each child's size for its analysis and review.

## Solution

Keep detailed work in child tickets; the Epic only groups it. A child may be an M Question for a small question or feature.

## Statuses

The Status path of an XL is not decided; see [Open points](../rules.md#open-points). Project workflows set `S5: Done` on close.

## Who does what

Follow [Testing roles](../../delivery/testing.md#roles) for children, and [Pull requests](../../delivery/workflow.md#pull-requests) for delivery.

## Components and parents

Group work with native child relationships; follow each child's size for Component limits. Use the [shared repository rules](../rules.md#shared-steps); the XL Component count is an [open point](../rules.md#open-points).

## Closing

Close with `Disposition: Released` only after all children are closed. See the [closing rules](../rules.md#shared-steps) for parents.
